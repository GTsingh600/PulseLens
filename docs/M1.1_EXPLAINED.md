# M1.1 scaffold: what was built and why

This is for everyone on the team before they start their track. It explains what the scaffold contains, the reason behind each choice, where it goes beyond `BUILD_PLAN.md`, and what each track should do first.

## 1. What M1.1 is

M1.1 is the shared foundation that all three tracks build on: the build commands, the config, the server entry point, the client pages, the JSON contract between them, session storage and test fixtures. It has no liveness logic yet. Its job is to let Track A (client), Track B (analysis) and Track C (decision + eval) work in parallel from hour 0 without disagreeing about shapes, paths or commands.

## 3. How to run it

```sh
make setup              # once
cp .env.example .env    # fill in secrets (see STATUS.md "Needs a human")
make server             # terminal 1: uvicorn on :8000 with reload
make client             # terminal 2: Vite on :5173
make tunnel             # terminal 3, for phones: HTTPS URL
make test && make test-client && make lint
make types              # after any change to server/pulselens/models.py
```

Without make: `python scripts/dev.py setup`, `python scripts/dev.py test`, and so on. Extra arguments go through: `make test ARGS="-k store"`.

## 4. Each piece, and why it is built this way

### 4.1 Makefile over `scripts/dev.py`

`CLAUDE.md` defines the commands as make targets, but half the team is on Windows, where make isn't installed and shells differ (PowerShell, cmd, Git Bash). Make recipes with `if [ ... ]`, venv paths like `.venv/bin/python` versus `.venv\Scripts\python.exe`, or `npm` versus `npm.cmd` break in one shell or another.

So every make target is a one-liner that calls `scripts/dev.py`, which uses only the Python standard library and handles the platform differences itself. Benefits:
- the same commands work on Windows, macOS and Linux, with or without make
- logic lives in readable Python, not in shell quoting
- `setup` uses `uv` if present (it downloads Python 3.11 automatically, as `CLAUDE.md` requires) and falls back to `python -m venv` with a warning if the version is wrong

### 4.2 `config.yaml` and `config.py`

`config.yaml` holds the SPEC §17 values exactly. `config.py` loads it into frozen pydantic models with `extra="forbid"`, so a typo like `uplaod_batch_ms` fails at startup instead of being silently ignored and falling back to a default nobody chose. `config_hash()` returns the sha256 that `eval/freeze.py` will record in `eval/FROZEN` (SPEC §15.3).

`load_secrets()` reads `.env` and returns secrets as `SecretStr`, so they don't appear in logs or reprs (a test checks this). Missing secrets are `None` rather than a crash, so `/api/health` and the tests run without a `.env`. M1.2 should refuse to sign pulses when `PULSE_HMAC_SECRET` is missing.

Paths can be overridden with `PULSELENS_CONFIG` and `PULSELENS_DATA`, which tests and the eval harness will need.

### 4.3 `models.py`: the contract, and the generated `types.ts`

The plan asks for the §4.6 models (`CheckResult`, `FamilyResult`, `SessionDecision`) mirrored in TypeScript. The scaffold goes further: **every** JSON shape in SPEC §4 and §5 is a model, including `meta.json`, the `frames`, `pulses` and `sensors` lines, every REST body and every WebSocket message.

Why: M1.2 (server WebSocket) and M1.3 (client pulse executor) start at the same moment in different worktrees. If each writes its own idea of `pulse_ack`, the first merge at gate G1 is where they find out they disagree. With the shapes fixed now, both sides compile against the same definitions.

Keeping two hand-written copies in sync is the kind of thing that slips at 3 a.m., so instead of mirroring by hand:
- `pulselens/tsgen.py` renders TypeScript from the pydantic models (Literal aliases become named union types such as `Route`; fields with defaults become optional)
- `make types` writes `client/src/shared/types.ts`
- `tests/test_types_sync.py` fails if the committed file differs from what the models produce

The rule "change both together" from `CLAUDE.md` is now enforced by a test rather than by memory.

Other details that carry project rules:
- `CheckResult.abstain(...)` builds a correct abstaining result in one call (rule 2: checks never throw).
- `CheckResult.quality` is validated to 0..1.
- `ApplicantResponse` and `ProbeResponse` use `extra="forbid"`, so code that tries to slip a `score` into an applicant payload fails validation (SPEC §5).
- `Label.skin_tone_mst` is optional and 1 to 10, commented as self-reported only.
- New field `client.accessibility_route`: SPEC §6.1 and §10 use the flash opt-out but §4.2 had nowhere to store it. Added, with SPEC updated in the same commit.

### 4.4 `store.py`

One folder per session, exactly as SPEC §4.1 lays out (`meta.json`, `frames/`, `frames.jsonl`, `pulses.jsonl`, `sensors.jsonl`, `events.jsonl`, later `results.json` and `chain.json`), plus a SQLite `sessions` table for listing and routing state.

Design points:
- **Session IDs are validated** against `s_YYYYMMDD_HHMMSS_xxxx` before any path is built. The ID arrives in URLs, so without this a request for `../../something` could read or write outside `data/sessions/`. Tested with traversal attempts.
- JSON files are written to a temp file and renamed, so a crash never leaves a half-written `meta.json`.
- JSONL appends hold a lock, because frame batches for one session can arrive concurrently.
- Only listed columns can be updated, and only known streams can be appended to.
- Each operation opens its own SQLite connection, which is safe under FastAPI's thread pool.
- Server times are ISO strings with an offset, used for audit only (rule 1).

### 4.5 FastAPI app

`api/main.py` has a `create_app(store=None)` factory and a module-level `app` for uvicorn. Tests pass their own store pointing at a temp folder, so tests never touch `data/`. The factory loads the config first so a bad `config.yaml` stops the server at startup. M1.2 and later add their routers inside `create_app`.

### 4.6 Client

- **Three Vite entry pages** (`index.html`, `record.html`, `console.html`) as SPEC §3 lists, built together. Each currently shows a placeholder and the server status.
- **Proxy:** `/api` and `/ws` go to `127.0.0.1:8000`. It is `127.0.0.1` rather than `localhost` because recent Node versions may resolve `localhost` to IPv6 `::1` while uvicorn listens on IPv4, which shows up as a confusing connection refused.
- **Tunnel:** Vite blocks requests with unknown `Host` headers by default, which would break `make tunnel` on the phone with a "Blocked request" page. `allowedHosts: [".trycloudflare.com"]` allows the quick-tunnel domain. `host: true` also lets phones on the same Wi-Fi reach the dev server.
- **One clock in code:** `src/shared/clock.ts` exports `now()` (which is `performance.now()`), and ESLint fails on `Date.now()` or `new Date()` in `src/capture`, `src/record` and `src/shared`. Rule 1 is checked by lint, not only by review. Verified by linting a probe file that used `Date.now()`; ESLint reported the rule.
- **Two TypeScript configs:** browser code (`tsconfig.json`) gets DOM types only; config files and Playwright tests (`tsconfig.node.json`) get Node types. This stops Node-only APIs from type-checking in browser code.
- **Playwright** is configured with the fake-camera flags M1.3 needs, and starts Vite on its own if it isn't running.

### 4.7 Tests and fixtures

`tests/fixtures/synth.py` is the start of the synthetic test kit (`CLAUDE.md`: no network and no real faces in tests):
- `frame_times(n, fps, jitter_ms)`: strictly increasing client-clock times; rejects jitter large enough to reorder frames
- `flat_frame(..., noise_sigma)`: a flat colour with optional sensor-like noise (for M2.4 noise checks)
- `textured_frame(...)`: random blocks with enough corners for optical flow (for M2.3)
- `jpeg_bytes`, `frame_records`, `light_pulse`, `client_info`, `session_meta`

Tests so far cover health, the abstain helper, applicant payloads rejecting scores, metadata round trips, the SPEC pulse example, the bundle layout on disk, frames and JSONL, unsafe session IDs, config values against §17 (including the "at most 3 flashes per second" spacing), unknown config keys, secrets, and the types sync.

### 4.8 Models download

`scripts/fetch_models.py` downloads the MediaPipe face and hand landmarkers (server, SPEC §8.1) and the BlazeFace short-range detector (client coaching, SPEC §6.4) into `models/`. It skips files already present, downloads to `.part` and renames, and writes `models/MANIFEST.json` with URL, size and sha256 per file, so results can later name the exact model that produced them. Hosting the detector ourselves means the capture page doesn't depend on a CDN over venue Wi-Fi. ArcFace and CLIP are fetched by their own libraries on first use, after `make setup-ml`.

### 4.9 Dependencies

- `make setup` installs `[dev,vision]`: FastAPI stack, numpy, Pillow, pytest, ruff, plus mediapipe, scipy and matplotlib so Track B can start M1.4 at once.
- `[ml]` (torch, insightface, open_clip, scikit-learn) is opt-in with `make setup-ml`. It is large (torch alone is a big download), and insightface may need a C++ build toolchain on Windows. Only whoever runs M2.5 or M2.6 needs it.

## 5. Problems found while building, and the fixes

| Problem | Fix |
|---|---|
| `make` isn't on Windows | Installed with `winget install ezwinports.make`; `dev.py` makes make optional anyway |
| mediapipe already installs `opencv-contrib-python`; adding `opencv-python-headless` gave two packages writing the same `cv2` folder, and removing one broke the other | Dropped the extra OpenCV, reinstalled contrib, and left a comment in `pyproject.toml` saying not to add a second one |
| ruff formatted `scripts/` at 88 columns and `server/` at 110, because the config only covered `server/` | Moved the config to a root `ruff.toml` |
| `tsc` failed on `vite.config.ts` (no Node types in a DOM config) | Split into `tsconfig.json` (browser) and `tsconfig.node.json` |
| Toolchain is newer than the plan assumed (Vite 8, Vitest 5, TypeScript 6, ESLint 10, mediapipe 1.1, OpenCV 5) | Everything builds and passes on these versions; the lockfile pins them for the team |

One warning is left: Starlette says using `httpx` with its `TestClient` is deprecated. It is harmless; Track C can switch when M1.2 adds more API tests.

## 6. Where the scaffold goes beyond the plan

1. **The whole contract up front** (`models.py` covers SPEC §4 and §5, not only §4.6), so parallel tracks don't drift.
2. **Generated `types.ts` with a drift test** instead of hand mirroring.
3. **Lint-enforced one clock** (ESLint bans `Date.now()` in capture code).
4. **Strict config** (unknown keys fail at startup) and a config hash ready for `FROZEN`.
5. **Path-safe session IDs** in the store.
6. **Cross-platform task runner** so Windows teammates aren't blocked on make or shell quirks.
7. **Model manifest with sha256**, and the client face detector served locally.
8. **Applicant payload models that reject extra fields**, as a first guard for "no score for the applicant".
9. **Vite ready for phones** through the tunnel and the LAN (`allowedHosts`, `host: true`, IPv4 proxy target).

## 7. What each track starts with

**Track A (client): M1.3 capture page.**
Replace `src/capture/main.ts` with the real page: startup checks (§6.1), the grabber with rVFC and rAF fallback (§6.2), the light executor (§6.3) and coaching (§6.4).
- Build `ClientInfo`, `FrameRecord` and `PulseAck` from `src/shared/types.ts`; take every timestamp from `now()` or the rVFC callback.
- For coaching, add `@mediapipe/tasks-vision` and serve `models/blaze_face_short_range.tflite` and the wasm files locally (`client/public/models/` and `client/public/mediapipe/` are already gitignored).
- Extend `tests/e2e/` with the full fake-camera session (≥ 200 frames, strictly increasing `t`, 8 ordered acks) and add the vitest tests for channel detection and pulse spacing.

**Track B (analysis): M1.4 light echo, then M1.5 CLI.**
Write `test_light.py` first, using `synth.frame_times` and new helpers in `synth.py` for skin and background ROI means with a known delay, amplitude and colour. Then:
- `vision/frames.py`, `vision/face.py` (`models/face_landmarker.task` is already downloaded; note that mediapipe here is 1.1, so check the Tasks API against its docs)
- `checks/optical_light.py`, returning `CheckResult` and using `CheckResult.abstain(...)` for every bad-input path

For M1.5, add `--bundle <dir>` to `synth.py` and write bundles through `SessionStore` so the layout matches the live server.

**Track C (decision + eval): M1.2 session API and WebSocket.**
Add `api/sessions.py` and `api/ws.py` and include them in `create_app`.
- Use `SessionStore` for every write and `new_session_id()` for IDs.
- Request and response bodies are the models already in `models.py`: `CreateSessionRequest`, `ApplicantResponse`, `PulseMessage`, `PulseAck` and the rest.
- Sign pulses with `load_secrets().pulse_hmac_secret`, and refuse to start pulse release if it is missing.
- `test_api.py` can build JPEGs with `synth.jpeg_bytes` and frame lines with `synth.frame_records`.

**Everyone:**
- After changing `models.py`, run `make types` and commit both files.
- Before merging at a gate, run `make test test-client lint`.
- The open human items are in `docs/STATUS.md` under "Needs a human": `.env`, the consent form, cloudflared, and installing make/uv on Windows.
